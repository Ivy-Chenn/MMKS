    Algorithm Principle Knowledge

    The robot algorithm system is responsible for converting the information acquired by sensors into motion decisions that the robot can execute, enabling the robot to autonomously complete positioning, environment understanding, path planning, obstacle avoidance, and automatic recharging. A typical autonomous movement process can be understood as follows: the robot first determines its own status through information such as GNSS/RTK, IMU, Camera, and wheel speed, and obtains its own position and environment map via Localization and SLAM; Navigation calculates the travel route based on the current position, target position and the map;Obstacle Avoidance dynamically adjusts the route based on real-time environmental information; when the task is completed or the battery level is low, the Docking system is responsible for guiding the robot to return and accurately dock at the charging station. Therefore, the algorithm modules can be divided into Localization, Mapping \& SLAM, Navigation \& Obstacle Avoidance, and Docking four main sections. (../assets/pk/a1.png)

    Static Planning and Control

    • Advantages: Fixed boundaries, relatively simple logic, and high consistency; the map viewed by users is consistent with the map used by the robot.

    • Disadvantages: It has poor adaptability to positioning errors, positioning drift, and changes in the actual environment, and is prone to problems related to missing cutting or boundary control in boundaries/narrow passages and complex areas.

    Dynamic Planning and Control

    • Advantages: It is mainly reflected in the dynamic map logic. To adapt to the positioning error of about 10 centimeters in vision, the boundary will be dynamically corrected during the operation, and reset to the user's initial map after the operation is completed, so as to avoid user misjudgment. It can improve the boundary coverage rate, operation continuity and adaptability in complex scenarios.

    • Disadvantages: The planning and control logic is more complex, and the actual running trajectory may have a slight deviation from the user's initial map

    Positioning

    1.1 Basic Principles of Positioning

    The core task of Localization is to continuously estimate the robot's Pose, which refers to "where the robot is" and "which direction it is facing". For ground mobile robots, this can be simply understood as X, Y Position + Heading. A robot does not "know" its own position directly; instead, it continuously calculates and updates its position state based on information provided by multiple sensors.

    Positioning information can be mainly divided into Absolute Position and Relative Motion. GNSS/RTK can provide the position of the robot relative to the global or working area coordinate system, so it belongs to absolute positioning information; while IMU, Wheel Odometry and visual motion information mainly tell the robot "how much it has moved from the previous position", which belongs to relative motion information.Actual robots usually use two types of information simultaneously: absolute positioning is responsible for the long-term position reference, while relative positioning is in charge of short-term continuous motion estimation.

    1.2 GNSS and RTK

    GNSS (Global Navigation Satellite System) calculates the position of a robot by receiving signals transmitted by multiple satellites. A robot needs to simultaneously acquire information from multiple satellites and estimate its own position based on the satellites' positions and signal transmission data. GPS, Galileo, BeiDou and GLONASS all fall under the category of GNSS systems.Conventional GNSS typically only provides meter-level positioning accuracy, so for robots that need to perform high-precision operations along virtual boundaries or planned paths, relying solely on ordinary GNSS is usually insufficient. To further improve positioning accuracy, RTK Correction Data can be introduced on the basis of GNSS.

    1.2.1 RTK — Local Reference Station

    The core principle of RTK (Real-Time Kinematic) is to utilize a Reference Station with a known accurate position as a position reference. Both the reference station and the robot receive GNSS satellite signals simultaneously; since the reference station’s own position is known, it can calculate positioning errors based on the received satellite information and generate Correction Data. After receiving these correction data, the robot combines them with the satellite information it receives, thereby obtaining a more precise position result.

    The basic principle can be understood as follows:

    GNSS Satellite Signal + Local Reference Station Correction → High-Precision Robot Position

    In this approach, an RTK Reference Station usually needs to be installed near the robot's working area. The Reference Station itself requires good sky visibility to stably receive satellite signals, and a communication link for Correction Data from the Reference Station to the robot also needs to be established. Therefore, traditional RTK positioning relies simultaneously on the satellite signal at the robot end, the satellite signal at the base station end, and the correction data communication between the base station and the robot.

    When installing an RTK base station, the top priority is "co-view", which ensures that the rover and the base lock onto the same satellite.

    For example: 1. It is best to avoid having walls between the base station and the robots; 2. It is advisable not to install the base station in overly tall flower clusters. These measures can better ensure the elevation angle of the base station's coverage.

    Network RTK (VRS, Virtual RTK Station): A virtual reference station near the user is generated via cloud-based multi-station networking. It requires the device to have a stable 4G network, and a network disconnection within 1 minute will not affect positioning accuracy.

    1.2.2 NetRTK — Network RTK

    The basic positioning principle adopted by NetRTK (Network RTK) still falls into the category of RTK, but it differs in the source of Correction Data. Instead of requiring users to set up a local Reference Station in their garden, it utilizes the already deployed GNSS Reference Station Network to deliver RTK Correction Data to robots via network services.

    The basic principle can be understood as follows:

    GNSS Satellite Signal + Network RTK Correction → High-Precision Robot Position

    The robot first acquires satellite information via GNSS, and meanwhile obtains the Correction Data provided by the NetRTK service through network connections such as 4G / Wi-Fi / Internet, then combines the two sets of information to calculate a high-precision position.

    Therefore, the core difference between RTK and NetRTK is not that "one uses satellites while the other uses networks". Both require the robot to directly receive GNSS satellite signals, and the difference mainly lies in the source and transmission mode of RTK Correction Data. The Correction Data of Local RTK mainly comes from nearby local Reference Stations, while the Correction Data of NetRTK is sourced from a remote Reference Station Network and transmitted to the robot via the Internet.

    It can be simply understood as:

    Local RTK: Satellite → Robot + Local Reference Station → Correction → Robot

    NetRTK: Satellite → Robot + Reference Station Network → Internet → Correction → Robot

    One of the advantages of NetRTK is that it reduces the need for users to install and maintain local RTK Reference Stations on their own, but it also increases reliance on network connectivity and NetRTK Service Availability.Therefore, when NetRTK fails to work properly, in addition to checking GNSS Satellite Reception, it is also necessary to consider whether the robot can connect to the Internet normally, whether Correction Data can be obtained normally, and whether the relevant services are available.

    1.2.3 RTK Position Status

    Whether the Correction Data comes from Local RTK or NetRTK, the robot ultimately needs to calculate its own position based on GNSS information and the Correction Data. RTK positioning typically has different states, such as Single / Float / Fixed.

    Single means that the robot mainly relies on ordinary GNSS information for positioning, and a valid high-precision RTK solution has not usually been obtained at this time. Float means that the system has obtained RTK Correction Data and started high-precision calculation, but there is still certain uncertainty in the positioning result. Fixed means that the system has obtained a stable high-precision RTK solution, which is usually the most ideal state for high-precision path control.

    Therefore, "Correction Data connected" does not equate to "RTK has been Fixed". A robot requires both valid Correction Data and sufficiently good GNSS Satellite Reception to obtain a stable high-precision position.

    1.2.4 Environmental Influence

    Neither Local RTK nor NetRTK can address all GNSS environmental issues. Buildings, high walls, eaves and dense trees may block the satellite signals received by robots; walls, glass, metal structures and other objects may also cause signal reflection, resulting in Multipath effect, which degrades positioning quality.

    Therefore, even if the NetRTK network is properly connected or the Local RTK Reference Station is functioning normally, if the robot itself is located in a severely occluded area, there may still be cases where Fixed switches to Float, positioning accuracy degrades, or high-precision position cannot be obtained temporarily.

    From the perspective of Dealer Troubleshooting, the RTK positioning conditions can be simply understood as three parts:

    GNSS Signal Quality + Correction Data Availability + Communication Quality → RTK Position Quality

    For Local RTK, attention shall be paid to Robot GNSS, Reference Station GNSS and Correction Communication simultaneously; for NetRTK, focus shall be placed on Robot GNSS, Internet Connection and Network Correction Service.This can help identify whether the problem stems from the satellite environment, the Correction Data link, or network/communication conditions.

    1.3 IMU \& Wheel Odometry

    RTK can provide an accurate position reference, but it cannot independently describe the instantaneous motion changes of a robot, so the robot also requires IMU and Wheel Odometry to provide high-frequency motion information.

    An IMU typically perceives the linear and rotational motions of a robot via an accelerometer and a gyroscope. For instance, when a robot starts to turn left, the gyroscope can rapidly detect changes in angular velocity; when the robot traverses a slope or tilts, the IMU can also detect changes in its attitude.

    Wheel Odometry leverages the Encoder information of motors or wheels to estimate the moving distance of the robot based on the rotation amount of the wheels. For a differential-drive robot, if the travel distances of the left and right wheels are identical, the robot will basically move in a straight line; if the travel distances of the left and right wheels differ, the robot will turn.

    However, wheel odometry has a critical limitation: Wheel Rotation ≠ Always Actual Movement. If the robot slips on wet grass, muddy terrain, or a slope, the wheels may have rotated by a certain distance, but the actual distance the robot travels will be shorter. As a result, the error of wheel odometry will gradually accumulate over time.

    1.4 Sensor Fusion Multi-sensor Fusion

    As different sensors each have their own limitations, robots typically combine multiple information sources through Sensor Fusion. For example, RTK can provide a long-term and accurate position reference, but may be subject to occlusion in a short period; IMU features a fast update rate, but will generate drift after long-term use; Wheel Odometry can stably describe the normal driving process, but is affected by skidding; Camera can use environmental features to assist in judging motion and position, but is influenced by lighting and lens conditions.

    Therefore, the system continuously compares the information from different sensors and estimates the most reliable Robot Pose based on the current information quality. Its basic logic can be understood as follows:

    GNSS/RTK + IMU + Wheel Odometry + Vision → Sensor Fusion → Robot Pose

    This is also why a short-term drop in RTK signal does not necessarily mean that the robot immediately loses its positioning. The system can rely on other sensors to continue estimating motion, but if a reliable absolute position reference is missing for too long, the positioning error will usually gradually increase.

    Mapping \& SLAM Mapping and Simultaneous Localization

    2.1 Basic Principles of Mapping

    Localization addresses the question of "Where am I? ", while Mapping addresses that of "What does the environment look like? ". Robots continuously observe their surroundings via cameras, LiDAR or other environmental sensors, and then, based on their own position, place this environmental information into the correct spatial locations to build a map.

    The map used internally by the robot is not necessarily identical to the map displayed to the user in the App. Depending on different functions, the system may simultaneously maintain the boundaries of the working area, obstacle information, navigable areas, restricted zones, and the internal map for Navigation.

    A common map representation is Grid Map. The system divides the environment into numerous small grids, each of which can be marked as Free, Occupied or Unknown, meaning "traversable", "obstacle-present" or "unconfirmed" respectively. The robot can then determine which areas are passable based on this information.

    Navigation also frequently utilizes Cost Map. Instead of simply dividing the space into "traversable" and "untraversable", it assigns different traversal costs to various regions. For instance, the location of an obstacle is impassable, while areas close to obstacles, though passable, carry higher risks and thus incur higher costs. Navigation can leverage this information to select a safer route.

    2.2 Basic Principles of SLAM

    The full name of SLAM is Simultaneous Localization and Mapping, which refers to simultaneous localization and mapping. It addresses the problem of mutual dependence between localization and mapping: building an accurate map requires knowing the robot's position, while using the environment for localization in turn requires a map as a reference.

    The basic working process of SLAM can be simply understood as follows: as the robot moves, the camera or LiDAR continuously observes the surrounding environment; the system compares the environmental changes observed in two consecutive observations, and meanwhile combines motion information such as IMU and wheel odometry to estimate where the robot has moved from its previous position; then it adds the new environmental information to the map and keeps updating the robot's position.

    Therefore, it can be simply expressed as follows:

    Robot Motion + Sensor Observation → Pose Estimation → Map Update

    For example, when a robot sees a tree for the first time, it will record the position of the tree relative to the robot. When the robot continues to move and sees the tree again from another angle, it can further judge its own movement by comparing environmental features and correcting the positional relationship in the map.

    2.3 Visual SLAM \& LiDAR SLAM

    Depending on the main environmental sensors used, SLAM can take different forms.

    Visual SLAM primarily uses cameras to determine a robot's motion by comparing environmental features across consecutive images. For instance, when the position of the same stationary object shifts in successive frames, the system can leverage this change to estimate the motion of both the camera and the robot.

    LiDAR SLAM leverages laser ranging to acquire the distance and geometric contour of the surrounding environment, and compares the scan results obtained by the robot at different positions. If identical walls, trees or other structures exist in the two scans, the system can estimate how the robot has moved based on these geometric relationships.

    The two solutions have their respective characteristics: Camera can obtain rich visual and semantic information, but it is susceptible to the influence of lighting, stains and changes in environmental appearance; LiDAR can directly acquire distance and geometric information, and is generally insensitive to lighting changes, yet it may also be affected by the environmental structure, occlusion and sensor operating conditions.

    There are also different positioning methods when combined with RTK:

    RTK+Vision/RTK+Lidar

    It relies on the VIO visual-inertial odometry, and the error can be as low as only 1%.

    VIO: By fusing data from cameras and inertial measurement units (IMUs), it calculates the continuous displacement and attitude changes of a robot over short periods in real time

    SLAM: It refers to the technology of constructing a map of the surrounding environment while determining the robot's current position on the map based on sensor data.

    Lidar is mainly used for extending the lifespan of the system, and it can generally cover a distance of around 60 meters.

    Vision+RTK

    Visual-only localization: it will lead to the problem that the robot cannot work at night (around sunset), and since visual localization requires a large number of stored memory points, the storable map area will be relatively smaller accordingly.

    When paired with RTK, it can expand the working area, support nighttime operations, and reduce memory pressure.

    In scenarios where visual positioning fails (such as in forests and open areas), RTK can function as a repositioning solution.

    (When a robot is in an open environment, visual localization only provides a single viewing angle, so the robot rotates to supplement the field of view.)

    Lidar+RTK

    If the robot simply relies on LiDAR for positioning, it will easily encounter problems such as getting stuck, being unable to move, and being unable to re-localize.

    Due to the forward-tilted installation, the radar does not achieve full 360-degree coverage, which will also trigger a rotation action.

    2.4 Drift \& Loop Closure

    An important concept in SLAM is Drift. Every time a robot moves, there is a very small error in its position estimation. If the robot continues to operate, these small errors may gradually accumulate, resulting in a deviation between the position the robot perceives and its actual position.

    To reduce such cumulative errors, SLAM can leverage Loop Closure. For example, after a robot travels around a garden and returns to a location it has passed by earlier, if the system recognizes that "this is a place we have been to before", it can use this known correspondence to correct the previously accumulated errors in position and map.

    Therefore, SLAM does not simply and continuously add new environmental information to the map; instead, it is an ongoing observation → localization → mapping → reconfirmation → correction process.

    Navigation \& Obstacle Avoidance

    3.1 Basic Principles of Navigation

    When a robot knows its own position and has a map, it needs to decide "how to get from the current position to the target position", and Navigation is responsible for completing this process.

    Navigation typically requires several basic inputs: Current Pose, Target Position, Map, and Real-Time Obstacle Information. The system calculates a traversable path based on these inputs, and further converts the path into steering and movement commands that the robot can actually execute.

    Therefore, it can be simply understood as follows:

    Current Position + Target + Map → Path Planning → Motion Command

    For robotic lawn mowers, Navigation is not only used to travel from point A to point B, but also covers the movement from the charging station to the working area, transitions between different Zones, and the return trip once the task is completed.

    3.2 Global Planning \& Local Planning

    Navigation can generally be divided into two layers: Global Planning and Local Planning.

    The Global Planner calculates the general direction from the current position to the target position based on the overall map. For example, when a robot needs to move from the front yard to the backyard, the Global Planner will determine the overall route according to boundaries, restricted areas and known obstacles.

    The Local Planner is responsible for the actual movement of the robot in its current vicinity. Even if the Global Path has been determined, people, pets or temporary objects may still suddenly appear in the real environment, so the robot needs to continuously adjust its short-distance movement according to real-time perception results.

    It can be simply understood as:

    Global Planner: What's the overall direction we should take?

    Local Planner: How exactly to navigate these few meters right ahead.

    The combined effect of the two enables the robot to not only operate in accordance with the overall task, but also adapt to real-time environmental changes.

    3.3 Coverage Planning

    For robotic lawn mowers, another extremely important concept is Coverage Path Planning. While the goal of standard navigation is to move from point A to point B, the objective of coverage planning is to cover the entire working area as completely and efficiently as possible.

    For example, the common Zigzag Pattern is essentially a type of coverage strategy. The algorithm needs to comprehensively take into account factors such as the shape of the working area, the width of the robot, the path spacing, the boundaries, and the turning space to generate the operation route.

    Therefore, the question "why didn't the mowing robot strictly follow the sequence 1→2→3 to mow the lawn" does not necessarily indicate a path error. The system may readjust the execution order based on turning radius, remaining unmown area, path efficiency or real-time environment, and as long as the final goal of Coverage is met, such adjustment may still be a normal planning behavior.

    3.4 Obstacle Detection \& Obstacle Avoidance

    Obstacle Detection and Obstacle Avoidance are two related yet distinct concepts. Obstacle Detection addresses the question of "whether there is an object ahead and where it is", while Obstacle Avoidance deals with "what the robot should do after detecting such an object".

    Cameras, LiDAR, ultrasonic sensors, ToF sensors, bumpers and other devices can all provide obstacle information. After the system obtains the position and distance of obstacles, it needs to make decisions by combining the robot's speed, direction, available space and original path.

    Therefore:

    Sensor → Obstacle Detection → Environment Understanding → Avoidance Decision → Motion Adjustment

    Instead of performing the same action whenever any object is detected, the robot may choose to decelerate, stop, detour or re-plan its path depending on the specific situation.

    3.5 Static \& Dynamic Obstacles

    Obstacles can also be categorized into Static Obstacles and Dynamic Obstacles. The positions of trees, walls and fixed flower beds generally remain unchanged for a long time, so they can be regarded as part of the map; while people, pets or temporarily placed items may move at any time, thus their processing mainly relies on real-time environment perception.

    This is also why robots typically require both Map + Real-Time Perception: the map tells the robot "what is usually here", while real-time perception tells it "what is actually here right now".

    When the robot detects a temporary obstacle, the Local Planner can temporarily modify the current path; after the obstacle disappears, the robot can resume the original task without permanently modifying the entire base map.

    Docking Recharge \& Docking

    4.1 Basic Principles of Docking

    The goal of Docking (recharging docking) is to enable the robot to autonomously return to the charging pile and complete the final precise docking when it finishes work or needs to be charged. Different from ordinary Navigation, returning to the pile not only requires the robot to "arrive near the charging pile", but also requires the robot to enter the charging pile with sufficiently accurate position and orientation. Therefore, the entire process of returning to the pile can be divided into two main stages: Recahrging (recharging) and Docking (docking to the pile).

    The overall logic can be simply expressed as follows:

    Localization \& Navigation → Recharging → Within 5 m of Charging Station → Infrared Guidance → Fine Alignment → Docking

    Different information is adopted in the two stages to accomplish tasks with different precisions: the positioning and navigation system is first responsible for bringing the robot to the vicinity of the charging pile, and then the infrared guidance takes charge of the precise docking in the final stage.

    4.2 Recharging

    When a robot needs to be charged, it first enters the Recharging process. The system uses the current Localization information, Map and Charging Station Position to plan the route back to the charging pile.

    Essentially, this phase still falls under Navigation:

    Robot Position + Charging Station Position → Path Planning → Navigation → Approach Charging Station

    At this point, the system mainly addresses the following questions:"Where am I? ", "Where is the charging pile? ", and "How should I get back? "

    The robot does not need to directly detect the charging contacts throughout the entire return process; instead, it first relies on Localization and Navigation to return to the vicinity of the Charging Station.

    In the current product logic, when the robot enters a range approximately 5 m from the Charging Station, it can further enter the close-range Docking Guidance phase via Infrared Guidance.

    Therefore, if the robot is completely unable to return to the vicinity of the Charging Station, priority should be given to Localization, Map, Charging Station Position and Navigation, rather than initially diagnosing it as an Infrared Guidance or Charging Hardware issue.

    4.3 Docking

    After the robot has returned to the vicinity of the Charging Station, the system needs to further complete Docking.

    The problems addressed in this phase have shifted away from:"Where is the Charging Station located? "

    Transformed into:"At what position and orientation should I enter the Charging Station? "

    When the robot enters a range of approximately 5 m, it can further identify the direction of the Infrared Guidance to further recognize the direction of the Charging Station, and adjust its own movement so that the robot can correctly enter the charging pile.

    It can be simply understood as: Localization \& Navigation → Bring Robot Near the Station

    随后：Infrared Guidance → Approach \& Alignment → Docking

    Therefore, Localization / Navigation mainly addresses the return problem in a relatively large range, while Infrared Guidance mainly solves the short-range guidance issue after approaching the Charging Station.

    4.4 Charging

    After Docking is completed, the robot still needs to establish a valid Charging Connection before it can truly enter the Charging state.

    Therefore: Docked ≠ Charging

    The fact that the robot has physically entered the Charging Station does not necessarily mean that charging has been successfully completed.

    The normal process can be simply understood as follows:

    Docking → Charging Contact Established → Charging Detected → Charging Starts

    This phase involves the physical contact and electrical connection between the robot and the Charging Station. The robot can only enter the normal Charging State after the charging contacts are properly connected and the system detects valid charging conditions.

    Therefore, if the robot can return normally and complete the docking to the charging pile, but ultimately fails to start charging, then Localization, Navigation, and Infrared Guidance have most likely completed their respective tasks. At this point, the scope of the problem should be further shifted to:

    Charging Contact / Charging Station / Power Supply / Charging Detection / Charging Circuit

    and other charging-related processes.

    4.5 Obstacle Avoidance Logic for Docking Area

    After the robot approaches the charging pile, Obstacle Avoidance is disabled by default. This is a key difference between the charging docking process and standard Navigation.

    During normal operation, the robot needs to identify obstacles via its perception system and then stop or detour accordingly. However, the actual installation environment around the charging pile may be rather special; for example, users may add shelter structures similar to "dog houses" or other protective facilities outside the charging pile. If the robot still operates following the obstacle avoidance logic for ordinary working areas when near the charging pile, these structures may be recognized as obstacles, which will consequently prevent the robot from entering or leaving the charging pile properly.

    Therefore, disabling the conventional obstacle avoidance function near the charging pile is to ensure that the robot can complete the actions of leaving and returning to the charging pile in accordance with the established Docking Logic, without having the obstacle avoidance triggered repeatedly by the fixed structures around the charging pile.

    This also means that the Docking Area follows different motion and safety logics from regular work areas. When installing the charging pile, it is still necessary to ensure that there is space suitable for the robot to enter and exit near the charging pile in accordance with the product requirements.

    Algorithm System Summary - Relationships Between the Four Modules

    Localization, Mapping \& SLAM, Navigation \& Obstacle Avoidance, and Docking are not four mutually independent functions; instead, they share information on localization, maps and environmental perception to jointly form the closed loop of autonomous operation for robots.

    Localization serves as the foundation of the entire system, which is responsible for continuously determining the robot's position and motion status. Depending on the specific product, the robot can integrate various types of information including RTK / NetRTK, Vision, LiDAR, IMU, and Wheel Odometry to perform localization. As products iterate, the localization method has gradually evolved from being dominated by a single RTK to multi-sensor fusion, enabling the robot to utilize different localization information according to varying environmental conditions to maintain continuous and stable position estimation.

    Mapping \& SLAM further builds the robot's spatial understanding of the surrounding environment based on localization. The robot observes the environment using perceptual information such as Vision and LiDAR, and constructs or updates a map in combination with its own position; meanwhile, visual or geometric features in the environment can in turn assist the robot in localization and Re-localization. Therefore, Localization and SLAM do not have a completely unidirectional relationship, but rather provide mutual information and corrections for each other.

    After obtaining Robot Pose + Map + Real-Time Perception, Navigation \& Obstacle Avoidance determines how the robot will move next. Navigation performs path and coverage planning based on the current position, target position and map, while Obstacle Avoidance uses real-time perception information to handle temporarily emerging obstacles.With the development of product algorithms, the planning and control method can also evolve from Static Planning that mainly relies on fixed maps, to Dynamic Planning that integrates real-time positioning and environment perception information, so as to adjust the internal dynamic map and local boundaries during operation, and improve the coverage rate and operation continuity in complex environments.

    When the robot completes its task or needs to be charged, the system initiates the recharging process. First, via Recharging, the system continues to leverage Localization, Map and Navigation to guide the robot from its current position back to the vicinity of the Charging Station.When the robot enters the area approximately 5 meters from the Charging Station, the system further proceeds to the Docking phase, and completes short-range orientation judgment, position adjustment and final docking via Infrared Guidance. Near the Charging Station, the robot adopts dedicated Docking Logic and disables conventional obstacle avoidance by default, so as to prevent the Charging Station and its surrounding fixed structures from blocking the robot's normal undocking or docking process.

    After successful docking, the robot further needs to establish a valid charging connection and enter the Charging status. Therefore, docking and charging are two distinct concepts: docking addresses whether the robot can correctly access the charging station, while charging addresses whether the robot can establish a valid physical and electrical connection and start charging after being positioned on the charging station.

    Therefore, from the perspective of the information flow of the entire autonomous robot operation, the relationship among the four main algorithm modules can be summarized as follows:

    Sensors → Localization / SLAM → Robot Pose + Map → Navigation \& Obstacle Avoidance → Motion → Sensor Feedback

    When the robot needs to return for charging, it will further enter:

    Localization \& Navigation → Recharging → Near Charging Station (\~5 m) → Infrared Guidance → Docking → Charging Connection → Charging

    It should be noted that this is not a strictly unidirectional process, but a closed loop of continuous feedback and correction. For example, environment perception can help SLAM and Localization update the position, the new localization result will affect Navigation, and the motion generated by Navigation will in turn bring new Sensor Data, thereby updating the localization and map again. During the recharging process, the position and status of the robot will also change continuously, which will affect the subsequent Recharging and Docking behaviors.

    Understanding such upstream and downstream dependencies is particularly important, because the anomalies ultimately exhibited by a robot do not necessarily stem from the malfunctioning function itself. For instance, path deviation may arise from positioning errors, abnormal detours may originate from environment perception or planning and control logic, while issues related to automatic charging can be further divided into three stages:

    Failure to return to the vicinity of the Charging Station → Recharging / Localization / Navigation

    Returned to the vicinity but unable to dock → Docking / Infrared Guidance

    Successfully connected to the charging pile but unable to start charging → Charging Connection / Charging System

    Therefore, when troubleshooting issues, you can follow the steps below:

    Sensor Input → Localization / Map → Planning → Recharging → Docking → Charging

    Gradually determine which functional phase the abnormality occurs in, so as to avoid classifying all problems of "failure to recharge normally" as Docking Failure.
